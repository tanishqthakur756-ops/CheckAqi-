# India AQI-Weather Tracker

Backend originally generated by Cline from the earlier pseudocode/blueprint.
This pass: reviewed the backend for correctness, fixed several real bugs, and
added the frontend dashboard that was missing.

## How to run

```bash
cd backend
pip install -r requirements.txt
python -m app.seed_data          # populates the DB with demo data
uvicorn app.main:app --reload --port 8000
```

Then open **http://127.0.0.1:8000/** — the dashboard is now served directly
by the FastAPI app (mounted at `/`), no separate frontend server needed.
The raw API still lives under `/api/*` (see `/api` for a route list) and
`/health` for a health check.

## Bugs found and fixed in the backend

1. **NO2 and SO2 had identical breakpoint tables** (`analytics/aqi_calculator.py`).
   This was a copy-paste bug -- they are chemically different pollutants with
   very different CPCB tolerance ranges (SO2's "Moderate" band runs up to 380
   µg/m³, NO2's only to 180). Both now use their correct, distinct tables.

2. **`wind_correlation` was silently computing a temperature correlation.**
   `district_rollups` never had a wind column at all -- `avg_wind` didn't
   exist in the schema, model, or rollup logic -- so the API endpoint
   substituted `avg_temp` instead, with a comment acknowledging it. Added
   `avg_wind` end-to-end (schema.sql, models.py, schemas.py, rollups.py,
   api/districts.py) so wind correlation is now computed from real wind data.

3. **O3 breakpoint values didn't match the official CPCB table**, and an
   8-hr O3 reading above 208 µg/m³ had no defined breakpoint but was silently
   extrapolated into Very Poor/Severe anyway. Fixed the breakpoint numbers
   and capped over-208 8-hr readings at "Poor" (300) instead, since CPCB
   requires a 1-hr reading for anything more severe than that.

4. **PM10's boundary was off by 10** (351-420 instead of the official 351-430).

5. **`is_cpcb_compliant` was dropped from `compute_station_aqi`.** This flag
   (≥3 pollutants including one particulate) is what lets the frontend
   distinguish a fully-instrumented reading from a single-sensor guess.
   Restored it, along with `category`/`color` in the same response so the
   frontend doesn't need to duplicate that logic.

6. **`seed_data.py` never actually exercised the AQI calculator.** It picked
   a random target AQI and reverse-derived fake pollutant numbers from it
   (`aqi * 0.6` etc.) -- `compute_station_aqi` was imported but never called.
   Rewritten to generate plausible pollutant concentrations first and run
   them through the real calculator, the way live ingestion will.

7. **`daily_readings` and `district_rollups` were two independent random
   datasets** for the same dates -- rollups didn't actually average the
   station readings that were inserted, so the two tables could disagree
   with each other for no reason. Rollups are now derived by averaging the
   actual generated readings.

8. Updated `tests/test_aqi_calculator.py` for the O3 fix -- a few existing
   tests assumed O3 had a single continuous 0-500 breakpoint table (matching
   the old, incorrect implementation). CPCB's real spec only defines 8-hr
   breakpoints through "Poor" and 1-hr breakpoints for Very Poor/Severe, so a
   "moderate" 1-hr reading has no official mapping at all -- the relevant
   tests were corrected to reflect that instead of the old made-up numbers.

All of the above were verified by direct execution against the actual
extracted source (not just read through) -- see the calculator sanity checks
and the seed-data consistency check that were run during this fix.

## What's still unverified

- The full `pytest` suite (70 tests) couldn't be re-run in this environment
  (no network access to install fastapi/sqlalchemy/pytest here) -- the fixes
  above were verified with standalone scripts that exercise the same
  functions directly. **Run `pytest app/tests -v` yourself before trusting
  this fully** -- a few of the edited tests in particular deserve a look.
- The exact official CPCB breakpoint numbers for NO2, SO2, and O3 were
  cross-checked against one secondary source during this session, not the
  primary CPCB PDF -- worth a final check against CPCB's own published table
  before this goes anywhere near production.
- This still uses the ~12-station / 200-district demo seed data. Real CPCB/
  Open-Meteo ingestion (from the earlier blueprint's `ingestion/pipeline.py`)
  hasn't been wired in here -- `seed_data.py` is a stand-in for it.

## Project structure

```
backend/
  app/
    main.py                  # FastAPI app, mounts the dashboard at "/"
    db.py                    # SQLAlchemy engine/session, schema init
    models.py                 # ORM models (Contract A/B tables)
    schemas.py                 # Pydantic request/response contracts
    seed_data.py                # Demo data generator (fixed, see above)
    api/
      districts.py              # /api/districts/* routes
      sources.py                  # /api/sources/* routes
    analytics/
      aqi_calculator.py            # CPCB breakpoints + AQI math (fixed)
      rollups.py                     # daily_readings -> district_rollups
      correlation.py                   # Pearson r + seasonal pattern
      utils.py                          # IST/IMD helpers, DB lookups
    data/
      schema.sql                        # table definitions (fixed: +avg_wind)
      seed_districts.sql                  # ~200 Indian districts, LGD-coded
    static/
      index.html                          # dashboard (NEW -- was missing)
    tests/                                 # pytest suite (a few tests updated)
```
